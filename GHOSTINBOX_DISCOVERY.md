# Ghost Inbox API discovery - 2026-10-07

Source: https://temp-gmail.ghostinbox.net/ and its actual browser Network requests. Observed with ordinary Selenium Chrome, without stealth/challenge solver. Also replayed the browser POST with Axios and the server-issued session/CSRF; HTTP 200 confirmed.

## Verified create / shuffle / inbox

- GET / serves HTML containing the server-generated alias in input#heroUser. No client-side alias generator observed.
- Shuffle: GET /?shuffle=1; server supplies a new dot/plus Gmail alias.
- Go to Inbox: GET /confirm-gmail-alias?email=<URL-encoded alias>, then 302 to /inbox. This is a normal frontend route, not a guessed JSON create API.
- Cookies issued: XSRF-TOKEN and ghostinbox_session. Values are never included in this report. Keep cookies separately per VPS mailbox.
- GET /inbox serves the Livewire component bootstrap, CSRF token and signed snapshot. Component memo.name is frontend.app. Snapshot data includes messages, deleted, error, email, initial, overflow. PHP arrays are encoded as [payload,{s:arr}].
- Internal/undocumented JSON transport: POST /livewire/update. Content-Type application/json, X-Livewire empty, Referer /inbox. Browser fetch default Accept */*. Origin same origin for POST. Cookie session and body _token CSRF are required.
- Body: {_token,components:[{snapshot:<unchanged signed snapshot string>,updates:{},calls:[{path:"",method:"__dispatch",params:["syncEmail",{email}]},{path:"",method:"__dispatch",params:["fetchMessages",{}]}]}]} on initial load; refresh uses only fetchMessages.
- Response: {components:[{snapshot:<new signed snapshot>,effects:{returns,html,dispatches}}],assets:[...]}. Use the new snapshot for the next request; do not synthesize or modify its contents/checksum.
- Frontend polling interval: approximately 10 seconds while visible; stops fetching when IMAP error is present. The page has checkExpiry/resetTimer events and expiry countdown; actual expiration response still needs observation.
- Save Link uses GET /save-link and /mailbox/<token>; not needed for this integration. Do not return this token to AutoTouch.
- Attachment API has not been observed; out of scope.

## Verified message contract

- User sent a test email to an alias generated by our browser session. A subsequent normal browser refresh returned one message.
- Snapshot data.messages is a Livewire PHP-array tuple. Each message has subject, sender_name, sender_email, timestamp, date, datediff, id, content, attachments. Nested PHP array/object tuples must be unwrapped before normalization.
- timestamp is ISO 8601 with explicit timezone; id is a stable string (observed inbox-<digits>). content contains HTML, including the test body. No need to request a second message endpoint to extract OTP.
- Browser click on a[data-id] sends GET /message/{id}, with the same cookie session. This endpoint returns a normal HTML message page. Its attachments were not opened.
- No pagination fields were observed; snapshot has an overflow boolean. Do not claim full-history pagination support.
- Ordinary Axios replay with the exact Livewire request succeeded. Authentication uses the provider-issued cookie and CSRF/signed snapshot, no Authorization header observed.
- Actual long-term session/mailbox expiration and 429 were not triggered. Implementation will classify HTTP 419/401 as session expiration, invalid redirect as session expiration, 404 as mailbox expiration, and respect Retry-After. These are defensive classifications, not observed provider guarantees.

## Compatibility approach

Keep emailtick_mailboxes and /api/emailtick/* unchanged. Add a separate Ghost mailbox table; select providers through /api/mail/*. Reuse common OTP selection and the bounded AutoTouch polling flow. Ghost polling must be at least 10 seconds; do not introduce a 5-second upstream loop.
